=============================================================================
0. WHY THIS RE-TEST EXISTS
=============================================================================
2026-07-26/27 audit found the cost model used by every research script,
including anomaly_batch2.py, was wrong in three ways:
  (a) sum(zerodha_charges.calculate_charges(...).values()) DOUBLE-COUNTS,
      because the returned dict already contains a 'total' key equal to the
      sum of the other six. Must read ['total'] instead.
  (b) kite/config.py had wrong constants. Already fixed in this repo before
      this re-test (exchange 0.00297% not 0.00345%; intraday stamp duty
      0.003% not 0.015%; GST base now includes SEBI; DP charge Rs 13.5 added
      for delivery sells, previously missing entirely).
  (c) Slippage assumptions (0.05%/side used throughout) were measured to be
      ~3.8x conservative for NIFTY-scale names -- Roll estimator says the
      half-spread is ~0.013%.

This re-test fixes ONLY (a) in code (kite/research/anomaly_batch2_corrected.py
is a copy of anomaly_batch2.py with exactly that one line changed -- see the
script's own header comment for the diff). (b) required no new code change
since config.py was already corrected in a prior commit and both the
original and corrected scripts import it live. (c) is explored as a
sensitivity sweep across three SLIP values, since slippage was always a
frozen assumption in the spec, not a bug in arithmetic -- lowering it is a
"what if the assumption were more realistic" probe, reported at all three
levels so the reader can judge for themselves which is credible.

The pre-registered PASS criteria are FROZEN. Nothing about what counts as a
pass was changed. Only the cost measurement was corrected.

=============================================================================
0.1 IMPORTANT ARITHMETIC CAVEAT -- read before the tables
=============================================================================
Fixing the double-count bug (a) does NOT simply make the corrected run
"cheaper" than the historical run once (b)'s config fixes are folded in.
Checked directly with the numbers actually in play (position slot size =
CAPITAL/TOP_N = Rs 100,000/20 = Rs 5,000, is_intraday=False, one round trip):

  Historical run (buggy sum(.values()) code + STALE config: exchange
  0.00345%, no DP charge at all):            fee actually charged = Rs 22.34
  Corrected run (['total'] + FIXED config: exchange 0.00297%,
  DP charge Rs 13.5/sell added):             fee actually charged = Rs 27.04
  Delta: +Rs 4.70 per exit (corrected is HIGHER, not lower)

Reason: the DP charge was previously missing entirely (Rs 0), and it is a
FLAT Rs 13.5 per delivery sell -- exactly the kind of charge that "bites
small positions hardest" (per config.py's own comment). At this backtest's
Rs 5,000 slot size, the newly-added DP charge (+Rs 13.5) more than offsets
the relief from removing the double-count (roughly halving a ~Rs 22 fee).
Net effect on the FEE side alone, at these position sizes: essentially a
wash, slightly NEGATIVE for the strategy (very slightly higher realized
cost than history recorded).

This is exactly why, at SLIP=0.002 held fixed, Test B and C's corrected
numbers below are marginally WORSE than the historical (buggy) run, not
better -- e.g. Test B val Sharpe 0.79 (historical) -> 0.77 (corrected,
SLIP=0.002). The audit's framing ("past backtests over-charged, so verdicts
were harsher than reality") is true and dominant on the SLIPPAGE axis (0.2%
Rs 20 round-trip drag on a Rs 5,000 slot, versus a ~Rs 5 fee delta) -- it is
NOT true on the fee-model axis alone once the missing DP charge is properly
included. All of the improvement seen below as SLIP is lowered comes from
the slippage axis, not the fee-double-count fix.

3. EXPLICIT ANSWERS
=============================================================================

Q: Does Test C's Sharpe criterion (>= B&H Sharpe + 0.10) now pass at any
   slippage level?
A: YES, at reduced-slippage assumptions only. It FAILS at the original
   0.002 assumption (1.53 vs 1.55 required, still short by 0.02 -- almost
   identical margin to the historical run's 1.54 vs 1.55, since the fee fix
   nets to roughly a wash as shown in section 0.1). It PASSES at SLIP=0.0005
   (1.60 >= 1.55) and at SLIP=0.00015 (1.62 >= 1.55, the measured
   half-spread). So this ONE criterion is genuinely slippage-sensitive and
   flips from FAIL to PASS once slippage is assumed materially lower than
   the original 0.2%/side.

Q: Does Test C's OVERALL frozen verdict flip?
A: NO. PASS requires ALL 4 criteria. Criteria 3 (CAGR >= B&H - 3pts) and 4
   (no train/val sign flip) FAIL at every one of the three slippage levels
   tested, by large, clearly cost-insensitive margins:
     - CAGR is short by 13.1 / 12.9 / 12.8 points respectively -- no
       plausible cost assumption closes a 13-point CAGR gap; this reflects
       the strategy holding structurally lower-beta names, not a cost drag.
     - The train/val sign flip (train edge negative, val edge positive) is
       present at all three slippage levels and does not change direction
       as slippage falls -- it reflects a real difference between the
       train-era and val-era volatility regimes, not a transaction-cost
       artifact.
   Test C therefore remains FAIL -> tombstone under the corrected cost
   model, at all three slippage assumptions, including the most generous.

Q: Does Test B flip?
A: NO, not close. Both binding criteria (Sharpe, CAGR) fail by large,
   slippage-insensitive margins at every level tested (Sharpe short by
   0.78 / 0.61 / 0.58; CAGR short by 14.1 / 11.1 / 10.7 points). Criterion 3
   (no sign flip) passes at all three levels but that alone cannot produce
   an overall PASS. Test B remains FAIL -> tombstone under the corrected
   cost model at every slippage assumption tested.

=============================================================================
4. HONEST FRAMING
=============================================================================
Neither frozen verdict changes. This is not a case of "passes only at the
most generous slippage assumption" (which would be weak evidence) versus
"passes at the original assumption" (which would be strong evidence) --
NEITHER test passes its OVERALL verdict at ANY of the three slippage levels,
including the most generous (0.00015, the measured half-spread). The single
data point that does move is Test C's Sharpe criterion, which flips from
FAIL to PASS once slippage drops below ~0.001 -- but per the frozen
all-criteria-required rule, that flip is immaterial: Test C fails on CAGR
and on the train/val sign-flip criterion regardless of any cost assumption,
generous or conservative.

Bottom line: the cost-model bugs found in the 2026-07-26/27 audit do NOT
rescue either Test B or Test C. Both remain tombstoned exactly as recorded
in the original anomaly_batch2_results.txt. The corrected run additionally
surfaces a caveat the audit's own framing did not anticipate: at this
backtest's position sizes (~Rs 5,000/slot), the newly-added DP charge (a
real, previously-missing cost) roughly cancels the relief from fixing the
double-count bug, so the fee-model fix alone, isolated from the slippage
assumption, is close to a wash (see section 0.1). All of the movement seen
as costs are "corrected" in this re-test comes from the slippage-assumption
sweep (c), not from the fee-arithmetic fix (a) or the config constant fixes
(b). Slippage remains the single largest lever on these verdicts, and the
frozen spec's original 0.2%/side assumption -- not the newly-measured
0.015%/side estimate -- is the one both original tests were pre-registered
and evaluated against.
